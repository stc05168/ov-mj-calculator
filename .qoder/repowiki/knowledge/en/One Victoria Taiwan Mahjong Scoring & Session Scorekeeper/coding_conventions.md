- Frontend pages declare their role via `data-*` attributes on `<html>` (e.g. `data-suite-app`, `data-tms-app`, `data-embedded`, `data-scheme-mode`) instead of class names, and read configuration from the shared `window.OVMJ_APP_CONFIG` object frozen at load time.
- Cross-frame communication between the suite shell and embedded calculators/scorekeepers uses a published global API object (`OVMJCalculator`, `OVMJSessionHost`) exposed by each iframe, with an explicit `ready` promise and event-driven result delivery rather than direct DOM access.
- All persisted payloads carry a `schemaVersion` string (`ov-mj-session/v1`, `ov-mj-calculation-result/v1`, `mahjong-test-result/v1`) and are validated server-side by checking the exact schema constant before any DB write.
- Backend endpoints use record types for request/response bodies and throw typed exceptions via `ApiProblem.badRequest/notFound/conflict` rather than returning error codes, keeping controller methods free of branching logic.
- JSON payloads are size- and shape-checked centrally in `ApiController.validatePayload` (max 2 MB, ≤5000 entries, required fields, value ranges) before being serialized to the `GameSession.payload` LOB column.
- Test harness scripts enforce integrity by computing SHA-256 hashes of canonical inputs (`test.html`, `mjConst.js`, `checkHandType.js`) and rejecting completion payloads whose source hashes differ from expected values.
