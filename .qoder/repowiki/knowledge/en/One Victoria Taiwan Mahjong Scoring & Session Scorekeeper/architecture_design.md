The project is a multi-page static frontend plus a small Spring Boot API. The root serves three entry points: `index.html` (guest redirect to `mahjong-suite/index.html`), `mj.html` (standalone hand-scoring calculator using `mj.js` + `mjConst.js` tile definitions), and `session-scorekeeper/index.html` (in-memory four-player session scorekeeper). `mahjong-suite/app.js` is the integration shell that embeds both the calculator and scorekeeper as same-origin iframes and bridges them via a published `OVMJCalculator` / `OVMJSessionHost` facade; it validates results against the `ov-mj-calculation-result/v1` schema before building a round draft (`handTai`, `note`, `isSelfDraw`) and calling `fillRoundDraft`. Guest mode keeps all state in memory only; account mode loads the online scorekeeper at `session-scorekeeper-online/`, which authenticates against the Java REST API under `/api` and persists the `ov-mj-session/v1` aggregate JSON into H2 or PostgreSQL. The backend (`backend/src/main/java/com/onevictoria/mahjong/`) is a flat Spring Boot app: `MahjongBackendApplication` bootstraps Spring, `web.ApiController` exposes `/api/auth/*`, `/api/me`, `/api/players`, `/api/sessions` with strict JSON payload validation (schema version, player IDs, entries ≤5000, 2 MB cap), `model.GameSession` stores the raw JSON payload with JPA optimistic locking (`@Version`), and `repo.*` are Spring Data JPA repositories. Cross-cutting concerns live in `web.AuthInterceptor` (bearer token → `accountId` request attribute), `web.WebConfig` (CORS, interceptors), and `web.ApiExceptionHandler`/`ApiProblem` (error responses). A single `app-config.js` at the repo root publishes `window.OVMJ_APP_CONFIG` (API base URL, guest/account entry URLs, timeout) consumed by every page; deployment must keep `index.html`, `app-config.js`, `mahjong-suite/`, `mj.html|css|js|Const.js|checkHandType.js`, and the two scorekeeper directories on the same origin because they communicate via same-origin iframe messaging. Testing is driven by Python harnesses (`run_tests.py`, `run_scorekeeper_tests.py`) that spin a loopback HTTP server, launch Chrome/Edge, parse a `test-completion` script tag, and write machine-readable results to `test-results/latest.json` and `scorekeeper-latest.json`.
