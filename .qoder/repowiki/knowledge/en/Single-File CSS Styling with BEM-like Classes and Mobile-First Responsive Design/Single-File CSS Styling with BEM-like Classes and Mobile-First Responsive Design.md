## What system/approach is used

The project uses a **vanilla CSS** stylesheet (`mj.css`) linked directly from the single-page HTML (`mj.html`). There is no CSS framework, preprocessor (SCSS/SASS), CSS-in-JS, or component library. The styling is written in plain CSS and loaded via a `<link>` tag in the document head.

## Key files and packages

- `mj.css` — the sole stylesheet defining all visual rules for the app.
- `mj.html` — the markup that references `mj.css` and provides class names consumed by the stylesheet.
- No external style dependencies; fonts are loaded from the system (`Microsoft JhengHei`, Arial).

## Architecture and conventions

- **Flat, global stylesheet**: All styles live in one file with no modularization, imports, or scoped styles. Selectors target classes defined in `mj.html`.
- **BEM-like naming convention**: Class names follow a consistent pattern using descriptive nouns and modifiers:
  - Block-level sections: `.section`, `.settings`, `.special-conditions`
  - Tile components: `.tile`, `.selected-tile`, `.exposed-tile`, `.winning-drop-zone`
  - Layout containers: `.tiles-container`, `.tiles-group`, `.selected-tiles-container`, `.condition-grid`
  - State modifiers: `.selected`, `.max-selected`, `.winning-tile`, `.drag-over`, `.touch-active`, `.disabled`
  - Semantic groups: `.character`, `.bamboo`, `.dot`, `.honor`, `.flower` for tile suit colors
- **CSS custom properties not used**: Colors, spacing, and sizes are hardcoded as literal values throughout the stylesheet (e.g., `#b71c1c` for accent red, `#f5f5f5` background, `10px` border-radius). There is no centralized design token system.
- **Layout approach**: Flexbox is the primary layout mechanism — used extensively for tile rows (`.tiles-container`, `.tile-row`), settings panels (`.settings`, `.setting-group`), and condition grids (`.condition-grid`).
- **Responsive strategy**: A single `@media (max-width: 480px)` breakpoint at the bottom of the file adjusts trash icon sizing and tile dimensions for small screens. The body is constrained to `max-width: 650px` and centered with `margin: 0 auto`, creating a mobile-first card-style layout.
- **Touch/mobile support**: Explicit touch handling via `-webkit-touch-callout: none`, `-webkit-user-select: none`, `user-select: none`, `touch-action: manipulation`, and `overscroll-behavior: none` on `html, body`. Drag-and-drop states use `.drag-over` and `.touch-active` modifier classes.
- **Visual hierarchy**: Sections use white backgrounds with `border-radius: 10px` and subtle `box-shadow` to create card-like containers. Accent color `#b71c1c` (dark red) is used for headings, buttons, and key highlights. Tile suits are distinguished by color classes applied to text content.

## Conventions and constraints

- **One stylesheet per project**: All styling is consolidated in `mj.css`; there are no additional CSS/SCSS files or inline styles beyond what's generated by JS.
- **Class-driven styling**: Styles are applied exclusively through class names on elements in `mj.html` (e.g., `.section`, `.tile`, `.drop-zone`); no element-type selectors are used for core UI structure.
- **State via CSS classes**: Interactive state (selection, drag-over, winning highlight) is represented by adding/removing modifier classes like `.selected`, `.drag-over`, `.winning-tile`, `.touch-active` rather than pseudo-states alone.
- **Tile sizing is fixed**: Tiles use fixed pixel dimensions (`29px × 52px` for source tiles, `35px × 40px` for selected tiles) with a responsive override only adjusting height at the 480px breakpoint.
- **No CSS variables or theming**: Colors and spacing are duplicated across rules; there is no theme switcher or dark mode — the palette is static.
- **Scoped reset**: A minimal CSS reset at the top (`* { box-sizing: border-box; margin: 0; padding: 0; }`) ensures consistent baseline behavior.
