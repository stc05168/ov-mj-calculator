Single-file vanilla JS SPA (`app.js`) paired with `index.html` (UI shell) and `styles.css`. The app owns two in-memory state objects: `session` (immutable-ish schema with players, config, entries) and `derived` (computed totals, stats, dealerState, chartPoints, handCount). All mutations go through `mutateSession`, which pushes an undo snapshot, applies a draft mutator, recomputes via `deriveSession`, persists via `saveSession`, and re-renders. `deriveSession` is the core engine: it iterates entries of type `discard`/`selfDraw`/`multiWin`/`draw`/`adjustment`/`breakPull`, accumulates deltas with a zero-sum invariant check, updates dealer streak/pull counters, and builds transfer lists plus chart points. A separate quick-ledger subsystem (`quickLedgers` Map keyed by player id) maintains per-opponent segments with exponential weighting (`1.5^n`) and automatic break-on-direction-reversal; settling converts to `adjustment` entries. UI rendering is split into small `render*` functions (`renderScoreboard`, `renderDealer`, `renderQuickLedger`, `renderHistory`, `renderChart`, `renderSettlements`, `renderSettings`) all invoked from `renderAll`. Data I/O uses JSON import/export with `normalizeSession` enforcing schema version `ov-mj-session/v1`, bounded integers, and physical-seat validation. A seat-dialog (`openSeatDialog`, pointer-drag swap) maps logical players to physical positions (`me`/`upper`/`opposite`/`lower`) used only by the quick ledger. Export paths include CSV, TXT (`buildTextExport`), JSON, and a Canvas-generated PNG share image. An optional `../app-config.js` host integration exposes `createHostedSession`, `getHostedSessionStatus`, and `markHostedSessionSaved` for server-backed sessions.
