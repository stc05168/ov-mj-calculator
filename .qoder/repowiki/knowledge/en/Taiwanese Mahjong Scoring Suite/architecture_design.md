The repository is organized as a multi-component application: the core scoring engine lives in `mj.js`/`mjConst.js`/`checkHandType.js` (loaded in strict order after `mjConst.js`) and powers both the standalone `mj.html` UI and the `mahjong_suite` iframe shell; `app-config.js` centralizes runtime wiring by exposing `OVMJ_APP_CONFIG` so the suite shells (`mahjong_suite`, `session_scorekeeper_online`) resolve the guest/account entry URLs and the backend API base URL at load time. The `session_scorekeeper_online` shell authenticates users and persists sessions to the `backend` Spring Boot REST API, while the `session_scorekeeper` provides an offline session recorder. A unified Python-driven test harness (`run_tests.py`, `build_test.py`, `check_tests*.py`) drives Chrome/Edge via Selenium against the same canonical fixtures in `test.html`, producing deterministic JSON evidence under `test-results/latest.json`; the exclusion rules for mutually exclusive hand types are centralized in `EXCLUSION_RULES`/`applyExclusions()` rather than scattered across detectors.
