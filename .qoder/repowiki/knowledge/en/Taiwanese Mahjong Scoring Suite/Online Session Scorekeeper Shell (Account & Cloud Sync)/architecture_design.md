Single-page shell (`index.html`) hosts two panels — an auth panel and a cloud-panel — plus an `<iframe id="scorekeeper">` that embeds the standalone `../mahjong-suite/index.html` as the actual scoring UI. All logic lives in `app.js`, which is wrapped in an IIFE and exposes a small test harness via `window.OVMJOnlineTest`. The shell communicates with the embedded suite through a postMessage-style contract: it reads `OVMJSessionHost` from the iframe's `contentWindow` and calls methods like `getSession`, `replaceSession`, `createSession`, `applyPlayerName`, and `markSaved`. A central `state` object tracks token, API base URL, workspace generation, saving/transitioning flags, and version maps for optimistic concurrency. All network calls go through a single `request()` helper that injects Bearer tokens, handles 401 logout, and uses `fetchWithTimeout` (AbortController-based) for bounded requests. Workspace operations are serialized with epoch/version checks (`captureWorkspaceEpoch`, `awaitInWorkspaceEpoch`, `requireCurrentWorkspaceEpoch`) so concurrent saves or loads cannot race. The shell also polls the embedded suite every 600ms via `readWorkspaceStatus` / `startWorkspaceStatusPolling` to keep the current-session badge and dirty-state indicator in sync. Configuration is injected at runtime via `window.OVMJ_APP_CONFIG` (loaded from `../app-config.js`), allowing deployment-time overrides of API base URL and guest entry URL.
