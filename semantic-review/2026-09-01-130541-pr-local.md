# Payload-bound session versions with shell-only legacy compatibility

The follow-up confines the `online-auth-001` compatibility binding to the legacy shell harness while preserving payload-bound optimistic versions in production. Client and backend validation now reject blank or mismatched payload IDs before version authority or persistence changes. The requested ownership, concurrency, dirty/auth teardown, guest-memory, iframe-loading, and score-transfer invariants remain intact, and the supplied test artifacts are green.

Watch for: No blocking issue remains in the requested follow-up scope.

**Verdict**: APPROVED

## High-level view

The list-version fallback requires both `shellTest=1` and a host without `getSessionStatus`. Production exposes that method and still rejects a listed session that has no payload-bound workspace version.

A returned payload ID must be nonblank and match the requested session before either successful GET or PUT can update `workspaceVersions`. The backend independently applies the same route/payload identity rule before persistence.

The fixes do not alter account scoping, expected-version checks, dirty or 401 behavior, memory-only guest state, authenticated iframe deferral, or the `handTai` transfer contract.
